# 麻專站工具箱

> 一套為了準備**麻醉專科醫師甄審筆試**而長出來的工具與工作流程。
> 這個 repo 放的是**方法**，不是內容——教科書衍生的筆記、圖表與題目都不在這裡。

*A toolkit of workflows built while preparing for the Taiwan anesthesiology board exam:
extracting figures from textbook PDFs, verifying every answer explanation against the
source text, remapping citations across textbook editions, and keeping a human in the
loop at every step. Documentation is in Traditional Chinese.*

---

## 這是什麼

準備專科考試的時候，最花時間的往往不是讀，而是這些瑣事：

- 詳解說「見 Miller 第 20 章 圖 20-3」，但你手上沒有那張圖，得自己翻 PDF 去截。
- 教科書改版了，舊詳解引的章節頁碼全部失效，而章節不是整齊地平移一號——有合併、有拆開、有整章被刪掉。
- 一份考古題詳解到底對不對？要逐題翻原文核對，六年六百題。
- 幾百題的題庫要逐題審，審到一半忘記審到哪、改了什麼。

這個 repo 記錄了處理這些問題的做法。每一套都在實際的六百題考古題與六十篇筆記上跑過，不是紙上談兵。

**共同的原則：機器負責找，人負責決定。** 下面每一套工具都會產出「候選」，但沒有一套會自動把候選寫進最終內容。跨過這條線的代價很高——實測關鍵字搜出來的候選段落大約只有一半是對的，看起來卻都很合理。

## 五篇文件

### 1. 從教科書 PDF 擷取圖表並對上題目
→ [`docs/01-figure-extraction.md`](docs/01-figure-extraction.md)

詳解提到某張圖，就自動去 PDF 的對應頁找出那張圖、裁切、壓縮、附到題目上。

處理的難題：圖說（caption）要一起裁進來否則讀者不知道在看什麼、同一頁有多張圖要挑對的、裁出來的候選要能讓人快速驗收。

### 2. 逐題人工審閱頁
→ [`docs/02-human-review.md`](docs/02-human-review.md)

一個跑在本機的小網頁，把待審的項目一題一題攤開，人只要按「可以／要改／存疑」並寫意見。判決存在獨立的檔案裡，**原始資料永遠是唯讀的**。

處理的難題：審到一半要能中斷續做、改完要能並排比對原版與新版來驗收、審查紀錄不能污染原始資料。

### 3. 跨版本章節對照
→ [`docs/03-edition-crosswalk.md`](docs/03-edition-crosswalk.md)

教科書改版時，把舊版的章節編號對應到新版。

處理的難題：**章節不會整齊地平移**。實際遇到的狀況包括兩章合併成一章、一章拆成兩章、整章被刪除、章節順序重排，還有一個「從某一章開始編號整體差一號」的系統性錯誤——那個錯誤是靠比對章節**標題內容**而不是編號才抓出來的。

### 4. 逐題引註查證與版本落差紀錄
→ [`docs/04-citation-verification.md`](docs/04-citation-verification.md)

把每一題詳解的說法拿回教科書原文逐字核對，核對過程中發現的「原文跟考題認定方向不一樣」「教科書自己前後矛盾」「新舊版說法不同」另外記成一份對照筆記。

處理的難題：怎麼確認引文是真的存在於原文而不是看起來很像、怎麼避免把「一段完整論證的中間一句」單獨切出來變成假的矛盾（這個錯誤真的發生過，而且是複審才抓到的）。

### 5. 實際遇到的問題與解法
→ [`docs/05-problems-solved.md`](docs/05-problems-solved.md)

流水帳，但可能是最有用的一篇。都是真的踩到、真的有代價、最後真的改掉的事：
資料被無聲清空、判決檔錯位、CDN 快取讓你「修」一個沒壞的東西、並列的說明裡
省略等於否定、`while read` 漏掉最後一行……

## 可以直接拿去用的東西

### 逐題審閱頁模板
→ [`template/review_server.py`](template/review_server.py)

單一檔案、只用標準庫，複製走就能跑：

```bash
python3 review_server.py --items questions.json \
    --show question,options,answer,explanation --port 8770
```

把任意一份 JSON 攤開來一題一題審，按「可以／要改／存疑」並寫意見，支援鍵盤操作、
「只看還沒審的」、隨時中斷續做。**來源檔全程唯讀**，判決另存成 sidecar。
欄位值是圖片路徑時會直接顯示成圖（需要 `--asset-dir`，且只允許讀該目錄底下的檔案）。

## 這個 repo 沒有什麼

**沒有任何教科書內容。** 沒有 PDF、沒有裁出來的圖、沒有筆記、沒有題目與詳解。那些是別人的著作，或衍生自別人的著作。

**所以這裡的程式碼沒辦法直接跑出成品。** 你需要自己準備來源素材。文件會寫清楚每套流程需要什麼樣的輸入。

## 一些實測數字

給想評估「這樣做值不值得」的人參考：

| 項目 | 數字 |
|---|---|
| 逐題查證的考古題 | 6 年 600 題 |
| 關鍵字搜出的候選段落，實際是對的比例 | 約 5–7 成 |
| 查證過程中發現的版本落差／教科書矛盾 | 75 則，附 168 則逐字引文 |
| 複審時被推翻的既有結論 | 28 則裡有 17 則 |
| 自動擷取但最終沒有採用的圖 | 109 張（產出 723 張、採用 614 張） |

最後兩行是重點：**複審推翻率超過六成，自動裁圖的採用率八成五。** 這就是為什麼每一套流程都必須有人工關卡——如果當初直接採信第一輪結論，站上現在會有十七則錯的內容。
